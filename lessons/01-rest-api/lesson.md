# Лекционный материал для подготовки

## Что такое UML и Sequence Diagrams
**UML (Unified Modeling Language)** — это унифицированный графический язык моделирования, предназначенный для визуализации, спецификации, проектирования и документирования программных систем. Он позволяет разработчикам, архитекторам и бизнес-аналитикам говорить на одном языке, используя стандартизированные диаграммы.

**Sequence Diagram (Диаграмма последовательности)** — это один из видов диаграмм взаимодействия (Interaction Diagram) в UML. Она показывает, как объекты или компоненты обмениваются сообщениями во времени для выполнения определенной функции или сценария. Главная ось на такой диаграмме — **время** (сверху вниз).

## Основные элементы диаграммы последовательности

| Элемент | Описание и использование | Графическое представление |
| :--- | :--- | :--- |
| **Актёр (Actor)** | Внешняя сущность (пользователь, внешняя система), которая инициирует взаимодействие. Находится за пределами моделируемой системы. | Схематичный человечек или прямоугольник с подписью `<<actor>>`. |
| **Участник (Participant / Lifeline)** | Компонент системы (Контроллер, Сервис, БД, Внешнее API). От участника вниз идет **Линия жизни (Lifeline)**. | Прямоугольник с названием и пунктирная линия вниз. |
| **Блок активации (Activation Box)** | Тонкий прямоугольник на линии жизни. Показывает период, в течение которого объект выполняет действие (обрабатывает запрос). | Узкий вертикальный прямоугольник на Lifeline. |
| **Синхронное сообщение** | Отправитель ждет ответа от получателя, прежде чем продолжить работу. | Сплошная линия с **заполненным** треугольным наконечником (`->>`). |
| **Асинхронное сообщение** | Отправитель не ждет ответа и продолжает работу. | Сплошная линия с **открытым** (линейным) наконечником (`- >>`). |
| **Ответное сообщение (Return)** | Возврат результата выполнения метода или запроса. | Пунктирная линия с открытым наконечником (`-->>`). |
| **Сообщение самому себе (Self-message)** | Вызов внутреннего метода объекта (например, валидация или хеширование). | Изогнутая стрелка, возвращающаяся к тому же блоку активации. |

## Комбинированные фрагменты (Операторы)
Используются для описания логики (условия, циклы) внутри последовательности:
*   **`alt` (Alternative)** — Условие `if/else`. Диаграмма делится на секции (например, *Успех* и *Ошибка*).
*   **`opt` (Option)** — Условие `if` (без `else`). Действие выполняется только при соблюдении условия.
*   **`loop` (Iteration)** — Цикл. Указывается условие или количество повторений (например, `loop 3 раза` или `loop до успеха`).
*   **`par` (Parallel)** — Параллельное выполнение нескольких потоков сообщений.

# Инструкции по настройке инструмента (VS Code + Mermaid.js)

**Mermaid.js** — это инструмент, позволяющий рендерить диаграммы (включая UML) из обычного текста (Markdown). Это идеальный выбор для System Design, так как диаграммы можно хранить в Git вместе с кодом.

### Настройка VS Code:
1. Откройте VS Code.
2. Перейдите во вкладку **Extensions** (`Ctrl+Shift+X`).
3. Найдите и установите расширение: [**Mermaid**.](https://marketplace.visualstudio.com/items?itemName=MermaidChart.vscode-mermaid-chart)
4. **Как использовать:**
   * Создайте файл с расширением `.md`.
   * Вставьте блок с кодом диаграммы, используя тройные обратные кавычки и тег `mermaid`:
     ````markdown
     ```mermaid
     sequenceDiagram
         participant A
         participant B
         A->>B: Привет!
     ```
     ````
   * Откройте превью Markdown: `Ctrl+Shift+V` (или `Ctrl+K V` для открытия сбоку).
